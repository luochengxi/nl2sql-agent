# 测试设计引导（不含缺陷位置）

> 本文件只列出**需要验证的能力域与测试方向**，不暴露缺陷的具体位置与修复方式。
> 建议先自己设计测试用例、跑一轮，再对照本地 `docs/缺陷答案key.local.md`（不进 git）。
> 项目本身**不含测试套件**——测试由项目所有者自行设计。

## 一、怎么切换被测对象

```bash
# 正常模式（作品集默认行为，所有测试应当通过）
python scripts/selfcheck_defect_switch.py

# 只激活一类缺陷，看你的哪条测试能抓到它
NL2SQL_DEFECT_MODE=D03 ./.venv/bin/python -m uvicorn src.api.main:app --port 8000

# 一次全开
NL2SQL_DEFECT_MODE=ALL ./.venv/bin/python -m uvicorn src.api.main:app --port 8000

# 或改 config/settings.yaml
defect_mode:
  enabled: true
  active: ["D03", "D05"]
```

`GET /api/defects` 在缺陷模式开启时会返回分类清单（只有分类与提示，没有位置）；
正常模式下返回空，避免对外展示时泄题。

## 二、建议覆盖的能力域

| # | 能力域 | 建议的测试方向（自己设计具体断言） |
| --- | --- | --- |
| 1 | 时间口径 | 滚动窗口边界（是否含当天）、自然周/月、季度、显式日期区间、默认窗口 |
| 2 | 周期对比 | 环比周期长度是否等长、同比是否按自然年对齐、对比期为空/为 0 的处理 |
| 3 | 行级权限 | 四种角色分别看同一指标，行数与数值是否符合组织树；父节点能否汇总子节点 |
| 4 | 下钻范围 | 点击汇总行展开明细时，是否只落在该行范围内、是否仍受角色 scope 约束 |
| 5 | 字段脱敏 | 手机号等敏感字段在各角色下的展现形态 |
| 6 | 禁用字段 | 被角色策略拒绝的字段/指标是否确实不可用 |
| 7 | 只读安全（注入） | 多语句、SQL 注释、参数里的特殊字符 |
| 8 | 只读安全（写操作） | DDL/DML 关键字、非白名单表、子查询 |
| 9 | 指标口径（复合指标） | 客单价等带分母的指标，分母口径是否正确 |
| 10 | 指标口径（状态过滤） | 有效订单量是否排除了取消/退款/待发货 |
| 11 | 意图澄清 | 同名不同口径时是否反问；反问后能否正确接上 |
| 12 | 槽位缺失 | 不带时间的问句用了什么时间范围 |
| 13 | 多轮记忆 | 追问时是否继承上轮指标/维度/筛选；新信息是否覆盖旧槽位 |
| 14 | 会话隔离 | 不同账号能否共用 session_id |
| 15 | 口径文档变更 | 产品/运营改完口径文档后，检索结果是否同步到新版本 |
| 16 | 数据导出 | 导出是否与界面同源、导出凭证是否绑定账号、CSV 中文编码 |
| 17 | 低置信兜底 | 无法理解时是否拒绝给数，而不是猜一个结果 |
| 18 | 审计留痕 | 各类操作（查询/澄清/导出/下钻/反馈/口径变更）是否都有记录 |

## 三、按角色准备测试数据

`config/rbac.yaml` 里内置 7 个演示账号，同一问句在不同账号下应得到不同结果：

| 账号 | 角色 | 范围 |
| --- | --- | --- |
| U001 | 超级管理员 | 全部 |
| U002 / U003 | 区域经理 | 华东 / 华西 |
| U004 / U005 | 城市经理 | 上海 / 成都 |
| U006 / U007 | 店铺管理员 | S001 / S007 |

建议把「同一问句 × 多账号」做成参数化用例——这是数据隔离类缺陷最有效的发现方式。

## 四、怎么判断你的测试"真的有效"

1. 正常模式（`defect_mode.enabled=false`）跑一遍：应全绿。
2. `NL2SQL_DEFECT_MODE=ALL` 再跑同一批用例：应有若干条失败。
3. 逐条 `NL2SQL_DEFECT_MODE=Dxx` 跑，确认「哪条测试抓到了哪类缺陷」。
4. 若全开时仍全绿，说明测试只覆盖了表面流程，需要补充断言（尤其是 SQL 文本、行数、
   敏感字段形态、时间区间端点、状态码这类**可断言的中间产物**）。

## 五、可断言的中间产物（比只断言"有回复"强得多）

- `ChatResponse.sql` —— 是否含权限条件、指标表达式是否正确
- `ChatResponse.plan` —— business_line / metrics / dimensions / time_range / confidence
- `ChatResponse.columns / rows / row_count`
- `ChatResponse.caliber_refs` —— 引用了哪条口径、哪个版本
- `/api/drilldown` 的 columns 与 rows
- `/api/export` 的状态码与文件字节
- `/api/audit` 的事件条数与 action 类型
- `/api/defects` 在两种模式下的返回差异
